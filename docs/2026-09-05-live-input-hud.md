# 实时输入与底部声纹

更新日期：2026-09-05。本轮未增加识别模型、云端接口或付费服务。

## 怎么用

1. 打开设置的「常规」，选本地 Paraformer 流式，语言选中文、英文或中英文。
2. 勾选「实时写入当前输入框」，保留快捷键直输，点击保存。
3. 先用鼠标点进需要输入的聊天框，把光标放在准备插入文字的位置，不要选中已有文字。
4. 使用录音快捷键。按住说话模式推荐 F8 等单键：按住录音，松开结束；点按模式则按一次开始、再按一次结束。
5. 软件框和目标聊天框都会更新。停止后仅补上剩余文字，不再次输入整段，不模拟 Enter 发送消息。

这不是每个音节零延迟出字：目标框接收连续两次识别结果一致的前缀，每约 250 毫秒检查一次可追加内容，实际延迟仍取决于音频切片和识别模型。软件自己的预览可以先显示还在修订的文字。

使用带 Ctrl、Alt、Shift 或 Win 的长按组合时，外部输入会等待修饰键释放，避免把字符误当成系统快捷键。需要长按期间实时出字时请选 F8 一类单键。

## 最小化状态

- 点悬浮球上的最小化，主窗口与悬浮球都隐藏，不占任务栏。
- 隐藏状态下启动录音，屏幕底部居中出现「正在输入」、实时声纹和计时。
- 指示条以录音开始时鼠标所在屏幕为准，使用该屏幕的工作区定位，在任务栏上方留出空间。尺寸为 220 × 44 DIP，顶部距工作区底部 100 DIP。
- 指示条不获取键盘焦点，鼠标可以穿透，避免影响原聊天框。
- 完成或取消约 1 秒后收起；遇到暂停或待确认结果约 4.5 秒后收起。可用原显示/隐藏快捷键或托盘恢复主窗口查看全文。
- 隐藏模式本次运行有效，重启后按原来的启动方式显示悬浮球。

## 输入保护与边界

实时模式只追加文字，不使用剪贴板，不回删原文，不全选覆盖，不修改 Num Lock。它会验证前台窗口、可编辑控件身份和光标前已有文字。

切换窗口、换输入框、移动光标、手动键入或点击鼠标后，本次实时外部输入会暂停。软件内继续保留识别结果，用户核对后手动复制需要的部分。暂停后不会尝试抢回焦点继续输入。

如果识别模型修订了已经写到外部的内容，也会暂停，不以退格删除或重写用户聊天框。取消录音不能撤销已经输入到外部的文字。

密码框、只读框、有选区的输入框、不提供所需辅助功能接口的控件以及权限阻止的目标不支持该模式。已验证自建 Chromium textarea 和 contenteditable 富文本框；这不代表所有第三方聊天软件已逐一验证。输入被拒绝时全文仍留在软件内，不自动降级成可能写错位置的整段粘贴。

## 与原有功能的关系

| 情况 | 行为 |
|---|---|
| 本地 Paraformer、普通语言、快捷键直输、实时开关开启 | 实时追加稳定原文，停止后补尾部 |
| 关闭实时开关 | 保留原来的停止后整理、预览和输入流程 |
| 中文转英文 | 录音时在软件内显示原文，停止后本地翻译，先确认再输入英文 |
| SenseVoice、Whisper 或云端转写 | 保留原来的完成后输入，不冒充实时流式输入 |
| 点击悬浮球录音 | 保留软件内录音预览；外部实时输入需要从目标框使用快捷键启动 |

实时外部输入以原文为准，保留简体转换及基础句末标点，不在结束时对已写入部分执行日常/条理 AI 改写、数字改写或词包替换，避免生成不同版本并重复输入。需要整理好的文字时，关闭实时开关，使用原先的确认后输入流程。词包和整理功能没有被删除。

## 验收

新增测试：

```powershell
npm run check
npm run test:live-input
npm run test:live-input-ui
npm run test:live-recording-ui
```

- 单元测试覆盖稳定前缀、只补尾部、识别修订、修饰键等待、暂停与取消。
- 原生输入测试使用隔离配置与自建输入框，覆盖原文保留、富文本、窗口内换字段、光标移动、选区、密码、只读、剪贴板不变、无 Enter 事件。
- 完整录音测试使用项目附带的 WAV，经 MediaRecorder 和真实本地 Paraformer 推理，再通过 Windows 原生键盘输入到测试框。分别验证正常双框更新、隐藏录音和中文转英文待确认。
- 声纹截图与窗口坐标检查验证居中位置、非空声纹、真实录音音量驱动、隐藏主窗口和不抢焦点。
- 自动化测试未向用户的实际聊天发送消息，也未逐一验证第三方软件或真实硬件 F8 的所有组合。

## 实现依据

- [Microsoft UI Automation GetSelection](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.textpattern.getselection?view=windowsdesktop-10.0)：读取选区与退化光标范围。
- [Microsoft 文本框自动化说明](https://learn.microsoft.com/en-us/dotnet/framework/ui-automation/add-content-to-a-text-box-using-ui-automation)：不同控件提供的模式不同，不能假定所有编辑器支持相同接口。
- [Electron BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window)：使用非聚焦窗口、showInactive 与忽略鼠标事件构建提示条。

实现文件：`src/live-input.js`、`scripts/live_input.cs`、`scripts/live_input.ps1`、`src/recording-hud.js`、`src/hud.html` 及对应预加载和样式文件。
